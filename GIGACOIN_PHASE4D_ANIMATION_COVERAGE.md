# GigaCoin Phase 4D — Animation Coverage

The manifest remains the 24-state, 98-frame-per-fighter contract (490 total). Only the 10 pre-existing Giga Champion idle/walk frames are validated production frames. The Phase 4C provisional set contributes 78 candidate poses; the Phase 4D sheets contribute 150 distinct provisional cells. The 228 provisional poses do not count toward production coverage. Counts in per-state rows are logical aliases; a Phase 4C walk cycle listed for both walk and run is one set of unique files, not additive new art.

The fixed-scale Phase 4D extraction uses a per-fighter scale calibrated from movement sheet row 1, column 1 (1-based), crops listed below at 4×4 cell coordinates (1-based), retains a 512×512 RGBA canvas and pivot (256,448), and uses edge-connected matte cleanup. The renderer selects Phase 4D frames when present, then falls back to Phase 4C candidates where declared, then procedural rendering. Browser runtime validation was blocked; runtime column reports unit-test evidence only.

## Important sequence limitations

- Phase 4D supplies two kick sequences per fighter (kick1 and kick2). Kick3 uses one fighter-specific Phase 4C candidate pose during its active hit window. None of the three kick actions has a complete five/six-frame production sequence.
- The two-frame signature candidates are concept/preparation/finish poses, not full character-specific motion cycles. Existing engine signatures still have their prior hit timing and hit-event logic; the renderer maps candidate poses to startup/active/recovery without changing hitboxes or damage.
- Most non-Giga idle, walk and combat candidates from Phase 4C remain provisional. Some fall/recovery/victory/defeat/turn states have no matching candidate and remain procedural.
- Provisional candidate counts can exceed one frame while still not satisfying the production contract because their poses and temporal sequences are not production-approved.
